## The tension, settled

The pointer is what the scope guard and completion audit judge edits against. A session that can move it can choose its own contract, and one that can clear it escapes any contract. So the answer is not "let the session run activate". The rule is: **a move that cannot widen scope is the session's own work; a move off an in-flight ticket needs the owner's own voice, carried by the one input the session cannot author (the UserPromptSubmit payload), never a pasted command.**

Safe for the session to run itself (must-allow):
- A. No pointer for this worktree -> activate the ticket. This narrows scope, from "everything" to one contract, and is what autopilot.md step 2 already does.
- B. The pointer already names the target: a no-op, reported as such.
- C. The pointer names a ticket that is closed **by a fact the session cannot write**: the review ledger under `<git-common-dir>/crew/` (already write-protected by scope_guard rule 2 and its shell check) holds an accepted/clean receipt for it, AND its spec header or INDEX row says done. INDEX/spec alone is not enough (finding 4).

Owner-only (must-block for the session, under every scope mode but `off`, like the existing shell refusals):
- D. `activate` away from, or `deactivate` of, a pointer naming a ticket that is open or whose closure cannot be told. "Could not tell" (unreadable ledger, unreadable spec, broken pointer) stays its own value and blocks. It never collapses into "closed".
