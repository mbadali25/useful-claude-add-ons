# T-0104 webtest scaffold for multi-module repos: detect modules, honour testDir, advisory gaps, no auth project without credentials, session config at the repo root          status: spec   risk: med

## Intent
`webtest_scaffold.py` becomes module-aware without giving up its additive-only contract (direction.md Option A, approved 2026-09-29 under standing authority). At a `--root` that is not itself a web project it lists the modules below it that are (bounded depth, `node_modules` and dot-directories skipped, the depth printed) with the exact `--module <dir>` command for each, instead of `n/a`. With `--module <dir>` (one per run, relative to `--root`) the module-scoped work - reading the existing `playwright.config.*`, the three test files under its `testDir`, the `.gitignore` lines - lands in the module, while the session-scoped files - `.mcp.json`, `.codex/config.toml`, `.claude/agents/` - land at `--root`, and `init-agents` is told the module's config (`--config <module>/playwright.config.ts`, Playwright 1.63.0's own option) so its seed test lands in the module's `testDir` and the agents at the root. An existing config's missing `setup`/`axe`/`visual` projects become advisory `gap` lines carrying a paste-ready snippet and stop driving exit 1; a `visual` snippet preserves baselines already named for an existing project; the auth `setup` file and project exist only when credentials are recorded (`.crew/secrets.md` at `--root`, or a `storageState` the config already declares); a `testDir` that is not a string literal is "could not tell" - nothing is written there and the line says why. `webtest_rules.py --module <dir>` emits the five rules scoped to the module (paths prefixed, `npx` commands run from the module in a subshell, guard commands given `--module`) and omits the axe and visual rules when the module's config lacks those projects, saying so; `webtest_guard.py auth-leak|visual --module <dir>` read the module's config and `node_modules` while git and `.crew/config.json` stay at the repo root. `/crew:init` Phase 6 loops over the detected modules one confirmed step each, and `/crew:webtest` takes `--module`. Crew bumps one patch past origin/main at push time (1.0.60 against `2693d0fa`, crew 1.0.59; re-fetch and re-bump if main moved).
