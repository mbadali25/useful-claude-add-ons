# L-0646: crew_ghdeploy.py watch - pass, fail or unknown from the run and its deploy job          status: spec   risk: high
Split from T-0045. Filed as L-0646.
## Intent
`python3 plugin/crew/hooks/scripts/crew_ghdeploy.py watch --root . --env <E> [--index N] [--slice-seconds S]` follows the run L-0645 identified and prints one verdict. Each call runs `gh run watch <id> --exit-status --interval 15` for at most one slice (default 540 seconds) or until the deadline `t0 + watchMinutes`; a slice that ends before the deadline exits 75 (call again). When the watch returns, `classify` reads `gh run view <id> --json status,conclusion,headSha,jobs,url` and answers pass (exit 0), fail (exit 1) or unknown (exit 3). The verdict and its reason are written into the state file and printed as the last line.
## Exclusions
- The watch exit code never decides the verdict.
- Never cancels, re-runs or approves a run. The only `gh` calls are `run watch` and `run view`.
- No write to `.work/PROMOTIONS.md` and no log excerpt (L-0647).
- No verdict on smoke, regression or verify: this is gate 2 only.
- No edit to `plugin/crew/tests/sabotage*.py`, promote-gate or autopilot.
## Evidence
Read at origin/main `155fe6d8` on 2026-10-04.
- plugin/crew/commands/promote.md:73-76 "Check the job, not the run": a conditional deploy step reports a green run having deployed nothing. :82 "Green means the workflow finished."
- gh 2.46.0 help, read 2026-10-04: `gh run watch` takes `--exit-status` and `-i/--interval` (default 3) and has no timeout flag. `gh run view` takes `--json`, `-j/--job` and `--log-failed`.
- The Bash tool's foreground limit is 600000 ms, so one slice must end inside it.
- Observed once on 2026-09-26 in the first consumer repository: `gh run watch <id> --interval 20 --exit-status` worked with that machine's token and exited 0 on success; about 80 seconds end to end with no queue.
- T-0045 defines `deployJob` (an fnmatch glob over job names), `shaInput` and `watchMinutes`; L-0645 writes the run id.
## Unknowns
- Whether `gh run watch` refuses some token types (its help says fine-grained tokens are not supported). Resolved by behaviour: a watch that cannot start still falls through to `classify`, which reads the run; if the view is unreadable too, the verdict is `unknown`.
- A run queued behind a concurrency group for longer than `watchMinutes`. Accepted: `unknown`, the run is left running and named.
