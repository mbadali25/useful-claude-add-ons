# T-0064 graph refresh honours the secrets denylist: default .graphifyignore and a refresh that never reads denylisted paths          status: spec   risk: high
## Intent
Crew never names or runs a graph build that would read a secrets-denylisted file. A new read-only checker, `crew_graph_ignore.py`, builds the repo's secrets denylist and lists every file on disk that matches it but that the root `.graphifyignore` does not exclude. `crew_refresh_check.py` refuses to name `graphify update .` or `graphify . --no-viz --code-only` while that list is non-empty, and names the files instead. `/crew:status` flags the same gap. `/crew:init` and a `--write` mode add the missing denylist patterns to `.graphifyignore`. The crew-graph skill documents the check and the runbook for a graph built before the fix (delete the output, fix the ignore file, rebuild). A fixture test runs the real graphify and proves that a denylisted file's symbols do not reach `graph.json` once `--write` has run, and that they do reach it without the ignore.
## Exclusions
- No edit to TheSelectSource or any other repo. TSS moving its guard's `PROTECTED`/`PROTECTED_DIRS` list into a file crew reads is TSS's own follow-up, cross-referenced by this id.
- No `/crew:graph` command and no autopilot behaviour change. The refusal reaches autopilot through the existing `unknown` + `refreshable: false` artifact, which it already stops on. `/crew:graph --refresh` is T-0067's, and it calls this checker.
- The refresh check stays read-only. It never writes `.graphifyignore`, because that write would fall outside the ticket's Touch at refresh time. It names `crew_graph_ignore.py --write` as the fix.
- No change to graphify, to its post-commit hook or to `graphify hook install`. A graph build typed by hand bypasses crew, and this ticket's answer to that is the init write and the status flag, not a wrapper.
- No new `.crew/config.json` key, and no change to the `.crew/*` un-ignore list (`check_crew_ignore_policy`). `.crew/config.json` is untracked, so a lane worktree would build the denylist without it and report "covered" wrongly.
- No deletion or rebuild of any existing `graphify-out/` here or elsewhere. The runbook is documented, not run.
- This repo's `.graphifyignore` is created only if the checker, run here at implement time, reports an uncovered file. Measured on origin/main `502cb137`: no tracked, untracked or ignored file here matches the default patterns.

## Unknowns
- **Denylist source (open question; the recommendation is taken, per the direction's Approval).** Recommended: the union of (a) crew's built-in patterns (`.env`, `.env.*`, `!.env.example`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `id_ed25519*`), (b) a tracked, optional, gitignore-syntax file `.claude/secrets-denylist`, which a repo's own guard can read as well, and (c) every `Read(<pattern>)` in `permissions.deny` of `.claude/settings.json` and `.claude/settings.local.json`. The alternative, `.crew/secrets-denylist`, needs the closed `.crew/*` un-ignore list changed in every place `check_crew_ignore_policy` guards. That is an owner decision, so it is not taken here.
- **Claude Code's anchoring of `Read(/x)`** (root of the project, or the settings file's directory). Implement step 1 resolves this from the Claude Code permissions documentation. Until then, and if the documentation is unclear, the checker adds the pattern under both readings, because a larger denylist can only require more coverage. `Read(~/…)` and `Read(//…)` outside the repo are out of scope and skipped by name. A bare `Read`, `Read(*)` or `Read(**)` is `unknown`, because no ignore file can express "deny every read" usefully.
- **git's matcher and graphify's may disagree** on an edge pattern. If git says "ignored" where graphify reads the file, the check fails open. Mitigation: the real-graphify fixture test covers the directory (`config/`), anchored (`/init.php`), extension (`*.pem`-style) and nested forms, in both directions. Any other disagreement is accepted as risk and noted in the skill.
- **Nested `.graphifyignore` files** could re-include a path with `!`. The checker evaluates the root file only, so a nested `.graphifyignore` on disk makes the result `unknown` and names it. It never passes.
- **An unknown stays unknown.** Git missing, `.claude/settings*.json` unparseable, `.claude/secrets-denylist` or `.graphifyignore` unreadable, or a listing git could not give: each is exit 2 / `unknown` with its reason, in the checker, in the refresh check and on the status line. None of them reads as covered (root CLAUDE.md, Lessons).
- **Landing order.** T-0063 also edits `crew_refresh_check.py`, and T-0070 also edits `crew_status.py`. Neither has landed. Whichever lands second rebases. Each step re-greps its anchors first, and tests assert on output, not line numbers.
- **Windows.** Crew runs git from Python with native paths and puts the patterns in the scratch repo's `.git/info/exclude`, so no path goes through an MSYS argument. Not run on Windows here, and the report says so.
