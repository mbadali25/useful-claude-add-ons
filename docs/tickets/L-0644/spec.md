# L-0644: crew_ghdeploy.py prepare - refuse or snapshot before a GitHub Actions dispatch          status: spec   risk: high
Split from T-0045. Filed as L-0644.
## Intent
`python3 plugin/crew/hooks/scripts/crew_ghdeploy.py prepare --root . --env <E> [--index N]` decides whether a GitHub Actions dispatch for environment E may be attempted, and if so records what is needed to find its run afterwards. It refuses with exit 2 and writes nothing on any problem. On success it writes `.crew/.ghdeploy/<env>-<N>.json` atomically (env, index, workflow, ref, sha, actor, t0, the snapshot of existing run ids, the correlation id, the command, identifySeconds, watchMinutes, deadline) and prints the dispatch command. It never dispatches.
## Exclusions
- No dispatch and no mutating `gh` call. The only `gh` calls are `api user`, a GET of `api repos/{owner}/{repo}/commits/<sha>`, a GET of `api repos/{owner}/{repo}/branches/<ref>` and `run list`.
- No copy of T-0009's classifier and no second authority decision. `prepare` calls `crew_guards.dispatch_scopes` and `crew_guards.dispatch_environment` read-only and compares the class with the environment's; it never reads unattended state.
- No `identify`, `watch` or `record` (L-0645 to L-0647). No promote-gate or autopilot change. No edit to `plugin/crew/tests/sabotage*.py`.
- No edit to `cloud_guard.py` or `crew_guards.py` unless T-0009's merged API cannot be called read-only; if it cannot, stop and amend this spec first.
- A workflow that `environments.workflows` does not list is refused (`unmapped-workflow`), never treated as nonProd.
