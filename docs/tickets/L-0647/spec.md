# L-0647: crew_ghdeploy.py record and the /crew:promote github sequence          status: spec   risk: high
Split from T-0045. Filed as L-0647.
## Intent
`python3 plugin/crew/hooks/scripts/crew_ghdeploy.py record --root . --env <E> [--index N]` writes the outcome of one dispatch into `.work/PROMOTIONS.md`, rebuilt whole through a temp file and `os.replace`. It always appends one detail line with no pipe character: `- deploy <env> <sha40> github <workflow>@<ref> run <id|none> <pass|FAIL|unknown|could-not-tell> <url|-> at <UTC> - <reason>`. On anything but pass it also appends the previous all-pass sha for that environment, the last 40 lines of `gh run view <id> --log-failed` (ANSI stripped, every pipe shown as a slash, each line clipped to 300 characters, indented), and the table row `| <UTC> | <env> | <sha40> | not-run | not-run | not-run | <actor> |`. `/crew:promote` gate 2 runs the five steps for a `github` environment and its `--dry-run` prints `check`'s output.
## Exclusions
- No automatic rollback, no re-dispatch of an older sha, no cancel. The record names the previous good sha; a person chooses.
- On pass, `record` writes the detail line only. The table row is promote's, after gates 3 to 5, as today.
- No change to how promote-gate or verify-gate read PROMOTIONS.md, and no change to the first-row `passed()` behaviour (T-0062).
- No net growth of `plugin/crew/commands/promote.md` past its allowance without an owner decision.
- No edit to the consumer repository from this ticket. Its config change is that repository's own ticket.
- No edit to `plugin/crew/tests/sabotage*.py`, promote-gate or autopilot.
## Evidence
