## Decisions (owner, Matthew Badali, 2026-09-25; `direction.md` "Decided")

- A lane never prompts the owner. It stops and writes its question or approval request, and the main session batches every lane's items to the owner in one message.

## Intent
`/crew:autopilot wave` runs a set of tickets the owner designed. **Design** happens in the main session: the set is built with `/crew:brainstorm`, `/crew:spec` and `/crew:plan` per ticket and recorded in `.work/autopilot/<set>.json`. **Approval** is one group approval (T-0024: `/crew:approve T-a T-b`, then `/crew:approve --confirm`). **Execution** runs every approved ticket whose dependencies are closed and whose Touch does not overlap another's as a lane: one `Agent` with `isolation: worktree`, whose first act is `crew_wave.py lane-init` (its ticket branch, the ticket folder and `.crew/config.json` copied in, the ticket activated, scope enforcing checked), then implement -> refresh -> review -> done checks inside that worktree. Lanes run concurrently up to `autopilot.maxLanes`. Each lane ends in one of four written states. `clean` means its done checks passed and it is ready to land. `findings` means its latest review round had findings. `question` means an item is waiting in `questions.md`. `failed` means the lane failed, with the reason. The main session then reports the whole wave, all open questions and approvals in one batch, and the landing order by version. This slice lands nothing. Landing stays T-0011's ship phase, applied one lane at a time in version order.

## Unknowns
- **Hard dependencies:** T-0004, T-0018, T-0024 and T-0010. All are in T-0029-wave (merge 1f54089e of T-0010-policies abd4f29b, which carries T-0024 32223b8a and T-0018 355b4d3a, plus T-0018-router d9fafa0a). None is on main yet. Anchors are re-read again after each lands.
- **PreToolUse in lane agents: resolved by the Step 1 spike (2026-09-26).** `Agent` lanes carry `agent_type`; with `isolation: worktree` the payload `cwd` is the lane worktree. Workflow is unmeasured and therefore disabled.
- **What `Agent` `isolation: worktree` checks out.** Measured: a new branch `worktree-agent-<id>` at `<repo>/.claude/worktrees/agent-<id>`, kept after the agent returns when it wrote files. Which commit it starts from was not measured, so `lane-init` never trusts it: it checks out or creates the ticket branch at the base commit `start` recorded.
- **A lane writing outside its worktree.** The guard judges a target against the payload `cwd`'s worktree and allows a path outside it (unchanged, owner decision). A lane Write aimed at another checkout's absolute path is therefore not refused by the guard; the lane prompt forbids it, and that checkout's own review and Stop audit are the backstop. Accepted as risk.
- **Whether a lane `Agent` can dispatch `crew:reviewer`** for the same-family review round. Not measured. If it cannot, the lane writes `question` naming the review it could not run, never `clean`.
- **Cross-session resume.** Accepted as risk. A wave never depends on it: `start` recomputes every lane's state from disk (ledger, lane file, worktree list), and a relaunch starts only lanes whose state is not terminal.
- **`autopilot.md` line budget.** It is at 100 of 100. The wave gets about 5 lines, found by rewrapping; all detail lives in `crew_wave.py` output. If it does not fit, the fallback is a backing skill, which needs the owner's yes (T-0018 Unknowns). It is not planned here.
- **Deciding whether two Touch lists overlap.** Two globs "might both match one path" is judged segment-wise with `crew_ticket`'s matcher. Anything the matcher cannot decide counts as overlap, and those tickets go into separate waves rather than running concurrently.
- **Dependencies of a ticket named without a set file.** They are read from the INDEX row's `(depends on ...)` text. If that cannot be parsed, the ticket's dependencies are `unknown` and the ticket is refused. This is never read as "no dependencies".
- Codex is out until 2026-10-01, so the review is same-family (crew:reviewer). Accepted as risk and announced.
