## Ask (owner Matthew Badali, 2026-09-30, relayed)

- **Ticket IDs.** New Linux tickets are `L-NNNN` (L-0509 is the first); Windows tickets are `W-NNNN`; existing `T-` IDs are never renamed. Every ID-handling site must accept any `[A-Z][A-Z0-9]*-\d+` ID uniformly.
- **COMPLETE ARCHIVE.** Completed tickets (INDEX status `done` or `merged`) will be moved to `.work/tickets/Complete/<ID>/`, and their Obsidian card note to `<vault>/<boardDir>/Complete/<ID>.md`, with the card line removed from Board.md's Done lane. This ticket makes every reader and writer Complete/-aware FIRST; the one-time move of the existing done tickets is an ops step AFTER it lands, not part of this ticket's code. Obsidian `[[ID]]` links keep resolving by name (Obsidian resolves by basename).
- **Crew docs rule, version, standing rules.** A `plugin/crew/` change updates every document that describes it in the same PR; the crew version goes one patch past whatever main holds at push (crew `plugin.json`, `.claude-plugin/marketplace.json`, `plugin/PLUGINS.md`); refresh artifacts and BUDGETS.md are always in scope.

Operational constraint carried from `.work/HANDOFF.md:27` (owner 2026-09-30 ~06:55): the later ops move never touches the cloud tickets (T-0500..T-0507, T-0104..T-0108), the win-repo-2 pointer ticket (T-0508), or a ticket a live lane still references.

## Options

1. **One resolver with an explicit "could not tell", routed everywhere; a reserved `Complete`; a tracker `archive` verb (recommended).**
   - `crew_common.locate_ticket(top, ticket)` (standard library, never raises) returns `(path, where)` with `where` one of `live`, `complete`, `absent`, `could not tell`: live dir if it exists; else `.work/tickets/Complete/<ID>` if that exists; `absent` (with the live path, for creation) when neither does; `could not tell` when a `stat` fails with anything but not-found/not-a-directory, or when BOTH exist (a half-finished archive). An unknown never collapses into "absent" (root CLAUDE.md, "an unknown collapsing into the safe-looking value").
   - `crew_ticket.ticket_dir` stays the public face: validates the id, calls `locate_ticket`, returns the path for `live`/`complete`/`absent`, raises `TicketError` for `could not tell`. Every self-built site in finding 1 routes through one of the two. `crew_common` lives beside every module, so modules that do not import `crew_ticket` (`review_prompt`, `review_run`, `crew_resume`) use `locate_ticket` directly.
   - `crew_common` holds the id shapes once: `TICKET_ID` (strict, anchored, ASCII digits), a search form for INDEX lines, `PLAIN_ID` (the loose path-safe form), `ARCHIVE_DIR = "Complete"`, and `reserved_id(name)` (case-folded, so `complete` is refused on a case-insensitive filesystem). Every copy in finding 4 becomes an alias; `check_ticket` in `crew_ticket`, `review_ledger` and `crew_metrics` refuses the reserved name.
   - `crew_status` counts live tickets and archived ones separately and never counts `Complete` itself.
   - `crew_tracker`: the note resolves live-then-`Complete/` (same could-not-tell rule); `create` treats an archived note as taken; `read` of an archived ticket reports it as archived (lane `Complete/`, INDEX status) instead of "no card"; `move` of an archived ticket refuses naming the archive. A new `crew_tracker.py archive --ticket <ID>` performs the move for ONE ticket: refuses unless INDEX says `done`/`merged`, refuses a ticket any worktree's active-ticket pointer names (or when that map cannot be read), moves the folder, then the note, then removes the card from the Done lane through the existing atomic `_board_write` - each half idempotent, reported on its own line. It never edits INDEX.md.
   - `crew_migrate._cache_source` labels by the configured tracker, not by the `T-` prefix; prompts say "next free id with this box's prefix".

   Tradeoff: touches ~15 modules and the scope guard's own-files rule (a guard blocking-decision change, stated in the spec and PR body), so it carries the full regression bar. In exchange the ops move becomes one tested command per ticket instead of hand `mv` plus a hand edit of a board Obsidian may be saving at the same moment.

2. **Same readers, no `archive` verb; the ops step is a hand-run `mv` and a hand board edit.** Smaller code change. Tradeoff: the board is the file crew already treats as fragile (`crew_tracker.py:738-745`: "a board that stops parsing opens as plain text in the human's window"), and the only code that edits it safely - exclusive temp, re-read, `os.replace`, no-follow directory walk - is `crew_tracker.py`. ~100 hand edits to a live board is where a clobber happens, and a half-moved ticket (folder moved, note not) is exactly the both-or-neither state the resolver must then report as could-not-tell. Rejected.

3. **Readers fall back by `glob` / `os.walk` over `.work/tickets/**/<ID>`.** Finds a ticket wherever it lands. Tradeoff: two matches become a silent pick, a walk error becomes "absent", and any future subfolder becomes a second archive nobody declared. Rejected - it is the collapse Option 1's `could not tell` exists to prevent.

## Recommendation

Option 1. One resolver, one set of id shapes, one reserved name, and one command that performs the archive with the same write discipline as every other tracker write. The one-time move of existing done tickets stays an ops step after merge (owner decision): this ticket ships the command and its tests, and running it over the backlog is not in its diff.

Scope note (not a file list; that is the spec's): a `plugin/crew/` change, so the project CLAUDE.md doc rule applies in full - README, the command and skill files that describe ticket location or ids, `plugin/PLUGINS.md`, the two affected guides plus their rebuilt HTML/DOCX/PDF, `.crew/codemap/`, `docs/diagrams/`. CONFIG.md gains nothing: no config key is added (it is named in the PR body's `Docs:` list with that reason). The crew version goes one patch past origin/main at push (1.0.71 as of `6813749b`).

## Open questions - settled under standing authority (written recommendation taken)

1. **Where does the resolver live?** Settled: logic in `crew_common.locate_ticket` (every script already sits beside it and it is standard-library only); `crew_ticket.ticket_dir` stays the validating entry point callers use today. One implementation, two doors, and a structural test that no other module joins `.work`/`tickets` itself outside a named allowlist (`crew_status`'s enumeration, `crew_migrate`'s 0.20 layout, `crew_tracker`'s note link written at create).
2. **Live and Complete both exist?** Settled: `could not tell`, naming both paths. Neither is picked. `archive` refuses to move into an existing destination, so crew never creates that state.
3. **Does archive touch INDEX.md?** Settled: no. The row stays with its `done`/`merged` status, which is what keeps the id taken for `create` (`crew_tracker.py:1345-1347`) and what every INDEX reader (finding 6) already handles.
4. **Does `/crew:done` archive automatically?** Settled: no. Archiving stays a separate, explicit per-ticket command; auto-archive at done is a follow-up to file after the ops move has run once. YAGNI.
5. **Bulk mode (`archive --all-done`)?** Settled: no. The ops step loops the per-ticket command over a list the operator reviews (the handoff's exclusions - cloud tickets, T-0508, live lanes - are a judgement, not a filter crew can compute).
6. **Un-archive?** Settled: out of scope. `move` on an archived ticket refuses and says the folder and note must be moved back by hand; `--reopen` does not bypass it.
7. **The note's `ticket:` link** (`crew_tracker.py:1227-1233`, a `file://` URI to the live folder, written once and never rewritten) goes stale after archive. Settled: accepted and documented; the note is never rewritten (`:1236-1240`), and the `[[ID]]` wikilinks that matter resolve by basename.
8. **Which prefix does a new ticket get?** Settled: no config key. `brainstorm.md`/`fix.md` say the next free number above every id in `.work/INDEX.md`, with this box's prefix (the prefix of the ids this box minted; `T-` when there are none). INDEX is per-box, so the last row minted here shows it. A config key is a follow-up only if this misfires.
9. **Unify the loose and strict regexes into one?** Settled: no - they answer different questions (a path-safe plain id vs an INDEX/board ticket id), and tightening the loose one would refuse ids tests and trackers use today. Both live once in `crew_common`; every copy aliases one of them.

Open questions remaining: none.
