# T-0063 worktree-aware reads: autopilot finds a ticket's INDEX row from the main checkout; refresh-check tells fresh from committed          status: spec   risk: med
## Intent
Autopilot's ticket-state reads work from a lane worktree. When the worktree's `.work/INDEX.md` has no row for the ticket, `crew_autopilot.py` reads the row from the main checkout (the first entry of `git worktree list --porcelain`). The answer says which checkout gave it, and two rows that disagree stop the run under a new stop id, `index-disagreement`. A ticket folder that exists only in the main checkout is named, with the copy to make, and it is never read as if it were local.

`crew_refresh_check.py` gets a fourth overall value, `fresh-uncommitted`: every artifact is current, but a refresh-artifact path has uncommitted changes (tracked and modified, staged, or untracked and not ignored). The CLI exits 1 on it. `/crew:done` check 4 refuses it. Autopilot names a `commit-refresh` phase that commits exactly those paths, before review and after an accepted review alike, because the review bundle is the working state and a commit does not change it.

The graph stops reading `stale` for ever after a change with no topology effect. When graphify's own `<graph.out>/manifest.json` records the current content hash of every code path the ticket changed, the graph is `fresh`, and the reason says graphify confirmed it.
## Exclusions
- No change to `crew_ticket.ticket_dir`, `touch_for`, the scope guard, the completion audit or the approval hook. They keep reading the worktree's own `.work/tickets/<id>/`. The main-checkout fallback is autopilot's INDEX read only. Reading the folder from the main checkout would let `next` name `/crew:implement` while the scope guard, which reads the worktree, finds no Touch.
- No write to either checkout's INDEX.md or ticket folder. Autopilot stays read-only (module docstring, `plugin/crew/hooks/scripts/crew_autopilot.py:11-13`). The copy is named for a person or the implement procedure to make.
- No git-backed coordination record. That is T-0030, and this ticket's resolver is one function (`_index_row`) that T-0030 can replace.
- No change to `crew_status.py`, `crew_state.read_work` or any other INDEX reader. Item 4 is autopilot's read.
- No change to graphify, its hooks or its manifest. The manifest is read, never written. A missing or unparseable manifest leaves today's sha comparison as it is. It never produces `fresh`.
- No change to `REFRESH_ARTIFACT_PATHS`, to the scope guard's or completion audit's refresh allowance, or to `crew_freshness.py`'s status line.
- No new `.crew/config.json` key, so `plugin/crew/CONFIG.md` is untouched.
- No edit to TheSelectSource. Its INDEX layout and its uncommitted artifacts are its own follow-up, cross-referenced by this id.

## Unknowns
- **Which checkout is "main" (resolved).** It is the first `worktree` record of `git worktree list --porcelain`. A record marked `bare`, a failed listing, or a path that cannot be read counts as "no main checkout", and the reason is kept. It never reads as "no row there". If the local row is also missing, the stop names both.
- **Disagreement (decided; the recommendation is taken, per direction.md's Approval).** Two rows disagree when both checkouts have a row for the ticket and their lower-cased status cells differ. That stops as `index-disagreement`, naming both paths and both cells. The alternative, "the main checkout always wins", would hide a worktree copy that has gone stale in the other direction, so it is not taken.
- **What autopilot does on `fresh-uncommitted` (decided; the recommendation is taken).** It names a new phase `commit-refresh`, not a stop. The command is `git add -- <paths> && git commit -m "<ticket>: commit refreshed artifacts"`, with each path quoted by `shlex.quote`. It applies before review and after an accepted review, because the bundle is the working state (Evidence). A test pins the bundle hash across the commit. The alternative is a human stop. That is safe, but it stops for a mechanical step the owner has asked autopilot to take (T-0067's direction). The no-progress guard (`last_command`) still stops a commit that does not settle it.
- **Which paths make a result `fresh-uncommitted` (decided).** Every path under the resolved `refresh_artifact_paths` that `worktree_changes(top, "HEAD", dirs)` reports, plus untracked files that are not ignored under those dirs. An in-scope artifact whose own file is among them reads `fresh-uncommitted`. An uncommitted refresh-artifact path that no in-scope artifact owns (a rewritten out-of-scope map, `.claude/rules/`) still makes the overall result `fresh-uncommitted`, because `/crew:done` would otherwise close with it unsaved. Ignored files (graphify's `manifest.json`, `cache/`) never count. Precedence: `unknown` > `stale` > `fresh-uncommitted` > `fresh`.
- **Manifest confirmation's limits (accepted as risk).** A `graph.json` restored by hand from an older commit, while the manifest is newer, would read confirmed. A code path graphify does not scan never appears in the manifest, so it stays `stale` as it does today. Implement step 3 re-reads every `save_manifest` caller in the installed graphify first. If any caller writes `ast_hash` without a successful `graph.json` write or a same-topology confirmation, the manifest part is dropped from this ticket, and the finding goes to `TODO.md`. It is never shipped on a guess.
- **Confirmation needs committed code.** The manifest confirms nothing while any reached code path is uncommitted. The existing "commit, then refresh" `stale` rule runs first, so a dirty tree cannot read `fresh` through the manifest.
- **Landing order.** T-0064 edits `_graph` in `crew_refresh_check.py`. T-0010, T-0029 and T-0067 edit `crew_autopilot.py` and `autopilot.md`. None has landed on origin/main `502cb137`. Whichever lands second rebases. Each step re-greps its anchors first, and the tests assert on output, not line numbers. T-0030 (approved, not landed) may later replace `_index_row`. It is not a dependency.
- **Windows.** Crew runs `git worktree list --porcelain` from Python with native paths and compares them after `os.path.realpath`. Not run on Windows here, and the report says so.
