## Intent
`/crew:autopilot goal "<goal>"` researches the goal once and writes a proposal. The proposal holds the goal, a one-line done-condition, the findings, and a split into tickets, each with a title, a risk and its dependencies, in dependency order, with the recommendation first. When the proposal is shown, autopilot also prints `/goal <condition>` for the owner to paste. The condition is rendered from the done-condition and is one line. It says that a stop naming a command only the owner types counts as met for now. Autopilot reports the line as `printed`, never as `set`, because it cannot observe Claude Code's goal state.

The split proposal is approved under `autopilot.approval`, with the goal's risk being the highest proposed ticket risk (unknown reads `high`). `self` approves. `risk` approves only when every proposed ticket is `risk: low`. `human` stops, naming `/crew:approve goal:<slug>` for the owner to type. Nothing approves it without `scope.allowCliApproval: true` and an armed autopilot. After the split approval, autopilot mints each ticket with T-0019's `crew_ticket.mint` (status `ready`, with a direction.md that points at the goal file). It then works the tickets one at a time in dependency order (`autopilot.mode: backlog`), within per-run caps. Each ticket reaches its own approve phase, where T-0010's `crew_autopilot.py approve --ticket <id>` applies the same policy to that one ticket. A refusal stops the run with that ticket's `/crew:approve <id>` line. Review acceptance and production deploys always stop for the owner. Goal state lives in `.work/autopilot/<slug>.json`. `resume: /crew:autopilot --goal <slug>` (T-0006's grammar) picks a run back up after `/clear`. T-0013 types it where the terminal can be identified; otherwise T-0006 names it for the human to accept (no `initialUserMessage`: T-0006's spike failed interactively).

## Unknowns
- **Decided (owner, 2026-09-26): "Follow the policy".** A ticket autopilot created (T-0019 assign, this ticket's goal minting) is approved under `autopilot.approval` like any other ticket. `self` approves it, `risk` approves only a `risk: low` ticket, and `human` stops. It must first pass `crew_ticket.py validate` and have no open question left unanswered under T-0010's `question_policy`. Review acceptance and production deploys always stop for the owner. Applied here to the split proposal (`split_policy`, with the goal risk) and to each minted ticket (T-0010's `approve`, one ticket at a time). This reverses T-0019's earlier rule that `approval_policy` answers `human` for any ticket with an `origin: /crew:autopilot assign` line. That rule never applied to goal-minted tickets, and it is gone.
- **Decided (owner, 2026-09-26): "T-0019 then T-0012".** T-0019 is built first. The `crew_ticket.py mint` primitive (next free id, folder, INDEX row, atomic, never reusing an id) moved from this ticket's former step 1 into T-0019. This ticket depends on T-0019 and reuses `mint`.
- **Open owner decision - `mode: backlog` must arm T-0010.** T-0010's `settings` arms only on the exact string `plan`, so under `backlog` its `approve` refuses everything, and `next` would not run either. Recommendation: `settings` arms on exactly `plan` or `backlog`, and `mode` reports which; every other value still reads as off with a warning. `approve`'s rule is unchanged otherwise, and a test pins that `backlog` grants nothing `plan` does not. Rejected: a second, backlog-only approve path (two approval routes to keep in step).
- **Whether `/goal` can be observed.** UserPromptSubmit is documented to fire for built-in slash commands (https://code.claude.com/docs/en/hooks.md), and `approval_hook.py` is a UserPromptSubmit hook. But recording `/goal` there would extend a blocking hook a second time. The goal also clears itself when met or impossible, or on `/goal clear`, and no hook event is documented for that. Decided: the status is only ever `printed`. Observing it is a separate ticket, if the owner wants one.
- **`/goal` pushing past a human stop.** The goal keeps Claude working until the evaluator says met. So the rendered condition ends with "or /crew:autopilot has stopped naming a command only the owner types", and the evaluator clears it at a human stop. Every gate refuses regardless of the goal: the approval hook, the scope guard and the review ledger. The line is printed again on each goal start or resume.
- **How a `human` split approval is recorded (needs the owner's explicit yes, because it extends a blocking UserPromptSubmit hook):** the owner types `/crew:approve goal:<slug>`. `approval_hook.py` accepts that one extra token shape, alone on the line, and writes `<git-common-dir>/crew/goals/<slug>/approval.json`, bound to the sha256 of `.work/autopilot/<slug>.json`'s `proposal` and tickets list. It is parsed before T-0024's group grammar and never joins it: `goal:` mixed with ids, two `goal:` tokens, the plain-text form and `--confirm` all record no goal receipt. Under `self`/`risk`, `split_policy` decides and is re-asked on every read, the way `crew_ticket.accepted` re-asks `approval_policy`. So a recorded `autopilot:<policy>` split approval in the goal file grants nothing by itself. Needs a must-block/must-allow suite and sabotage.
- A minted ticket's direction.md points at the approved goal proposal, and its INDEX status is `ready`, so T-0004's `next_phase` does not stop at direction-approval for it. The split approval stands in for each ticket's direction approval, and plan approval is still per ticket.
- Token cap: no hook input reports spend. It is measured as the sum of `message.usage` input and output across this session's transcript (the source `context-watch` already reads); unreadable means stop. Tickets cap: counted in the goal file across sessions.
- Reserved ids: `mint` (T-0019) skips ids listed in `.work/reserved-ids`. No reservation is outstanding (T-0013 is minted).
- The duplicate INDEX row (`/crew:spec` step 4 appends after `mint`) is T-0019's open owner decision. This ticket inherits it.
- Codex is out until 2026-10-01, so this ticket's review is same-family. That is accepted as a risk and announced.
