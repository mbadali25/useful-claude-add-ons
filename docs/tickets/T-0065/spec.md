# T-0065 crew hygiene from TSS: verify.json agents probed early, codex probed from the repo, review-bundle temp exports cleaned, crew_upgrade --force keeps UPGRADE.md history          status: spec   risk: med
## Intent
Four small, independent fixes for the crew 1.0.41 gaps TheSelectSource reported, one per item, each with its own test. (3) A read-only checker, `verify_agents.py`, lists every agent a `.crew/verify.json` rule names that is not installed on this machine. `/crew:status` shows the result as one line, and `/crew:verify` and `/crew:review` run the same checker instead of resolving names by hand. (10) A scripted provider probe, `provider_probe.py`, makes one real call to the provider from the repo root with review_run's own command line, so no agent has to type a `codex exec` from whatever directory it is in. (8) `crew_upgrade.py` keeps every earlier `UPGRADE.md` run below the new one, instead of overwriting the file. (7) Crew's hooks and test suites stop leaving temp files in the system temp directory: the auto-clear sender deletes itself first, verify-gate registers every temp file for cleanup, `run-tests.sh` removes every fixture it creates, and every pytest test gets its own `TMPDIR`.

## Unknowns
- **The UPGRADE.md layout.** The direction says "append", and an open question takes the recommendation. Recommended: put the newest run on top and keep the earlier file verbatim below one marker line, `<!-- crew_upgrade: earlier runs below, newest first; nothing below this line is rewritten -->`. With the newest run on top, `upgrade.md:167`'s "opens with" stays true, and so does `_carried_conflicts`'s read of the first `## Contradictions` section, with neither changed. The alternative, appending at the end, would need both rewritten. Either way the history grows by one report per run. That growth is accepted, because keeping it is the point.
- **Why the auto-clear senders survived.** Implement step 5 reproduces it first. It runs `test_auto_cycle.py` under a fresh `TMPDIR` and counts senders left behind. The recommended fix, unlinking the file as the sender's first command (POSIX keeps an open script readable after unlink), holds whatever the cause, SIGKILL included. The last-line `rm` stays as a fallback for a platform where an open file cannot be unlinked (Git Bash on Windows).
- **What Claude Code counts as "installed".** The checker counts user agents (`${CLAUDE_CONFIG_DIR:-~/.claude}/agents/*.md`), project agents (`<root>/.claude/agents/*.md`), crew's own roles, and the agents of every plugin in `installed_plugins.json` that the settings scopes enable, named `<plugin>:<name>`, by the frontmatter `name:` or else the file stem. It does not see managed-policy agents or agents passed with `--agents` on the command line. The line says so ("not checked: managed, --agents"). An unreadable registry or settings file makes a name `unknown`, never `installed`, so an unknown never collapses into a pass (root CLAUDE.md, Lessons).
- **The probe costs one real call.** It runs only when invoked, never from a hook or from `/crew:status`. The timeout is 120 s, and a timeout reports `FAILED - timed out`.
- **Landing order.** T-0064 and T-0070 also edit `crew_status.py`, T-0050 edits `crew_upgrade.py`, and T-0038 edits `commands/upgrade.md`. None of them has landed. Whichever lands second rebases. Tests assert on output, not line numbers, and each step re-greps its anchors first.
- **Windows.** The `.sh` changes have `.ps1` twins that are not changed here (see Exclusions). Nothing runs on Windows here, and the report says so. `pwsh` is on PATH on this host (`/snap/bin/pwsh`), so the suite's `@needs_pwsh` cases run.
