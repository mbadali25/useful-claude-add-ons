# T-0100 review bundle and completion audit account for merged main: a path byte-identical to the merged integration commit leaves both          status: spec   risk: med
## Intent
`review_patch.compute` and `completion_audit.audit` keep diffing from the ticket's recorded start (`scope_base.resolve`), then drop every path whose working-tree content and mode are byte-identical to the latest merged integration commit - `git merge-base HEAD <ref>`, `<ref>` being `scope_base._default_ref` (origin/HEAD, then origin/main, then main), read through that one helper so T-0061 can swap it. The rule lives once, in a new `plugin/crew/hooks/scripts/merged_main.py` (`resolve`, `keep`), so the bundle the reviewer reads, the receipt hash, the audit's changed set and the reviewer's prompt cannot disagree. A ticket edit on top of a merged-main edit to the same file stays in, and so does any out-of-Touch edit after a merge. When no merge of `<ref>` past the ticket start is reachable from HEAD, or HEAD is on `<ref>` itself, behaviour is byte-identical to today. When the merged commit cannot be determined (no ref names a commit, detached HEAD, a git error), the answer is "could not tell", nothing is dropped, and every derived line - manifest, review-patch stderr, the prompt's bundle block, the audit's verdict, the receipt check - says so. This is direction.md's Option 1 (owner's standing authority, 2026-09-28): a TOOLING change touching the review receipt, landing alone, one crew version past origin/main at push time (1.0.55 against origin/main `6387ab49`, crew 1.0.54; T-0075 is landing as 1.0.55, so the plan re-fetches and re-bumps).
