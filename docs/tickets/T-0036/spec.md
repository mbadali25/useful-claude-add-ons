# T-0036 /crew:reference --integrations and --flows: outbound API calls and end-to-end flows, anchored, linted and kept current by the refresh check          status: spec   risk: high
## Intent
`/crew:reference` gains `--integrations`, which writes `docs/reference/integrations.md`: every outbound call the repo makes, grouped by external system, each with its endpoint, auth scheme (naming where the credential comes from, never its value), request and response shape, retries and error handling, and every call site as `path:line`. It also gains `--flows [<name>]`, which writes `docs/reference/flows/<name>.md`: a one-line summary, a labelled Mermaid `sequenceDiagram`, an anchored step table, the state carried between steps, and "Failure and retry" and "What is not covered" sections. With no name it proposes candidate flows, recommendation first, and waits for the owner to pick. A new standard-library script, `crew_reference.py lint`, checks each doc's shape and anchors and refuses any secret-shaped string before the doc is written. `crew_refresh_check.py` judges these docs as a fourth artifact kind, so `/crew:implement` step 6 refreshes the ones a ticket's changes reach and `/crew:done` check 4 refuses a stale one. This happens automatically in crew's normal flow, as the owner asked on 2026-09-26.
## Exclusions
- No dependency on T-0035. A flow doc carries its `sequenceDiagram` as an inline fenced `mermaid` block. There is no `docs/diagrams/process/` file, no embed generator and no diagram readability lint here. T-0035 adopts these blocks when it lands (see Unknowns).
- No endpoint-ledger cross-check. `.crew/endpoints.json` records routes the repo EXPOSES (`implement.md:73-79` "A new externally reachable route"; `crew_endpoints.py:41-47`), not the hosts it calls, so it is the wrong list for outbound integrations (see Unknowns).
- `docs/reference/api.md` and `docs/reference/features.md` are not judged by the refresh check. They stay under the existing `--audit` and `.crew/verify.json` rule. Judging them is a follow-up (see Unknowns).
- No automated outbound-call detector over a ticket's diff. Whether a change adds an outbound call or a new flow is `/crew:docs`'s judgement at step 6, and `--audit` is the backstop.
- No generated `docs/reference/` for this repo. The feature is built and tested here with fixtures under pytest's `tmp_path`. Consumer repos (for example SRL/TSS order sync) get their docs when someone runs the command there.
- No change to `scope_guard.py`, `completion_audit.py` or `crew_autopilot.py` source. The guard and the audit read `REFRESH_ARTIFACT_PATHS`, and autopilot imports `ticket_freshness` (`plugin/crew/hooks/scripts/crew_autopilot.py:265-269`), so each gets the new kind and the new directory through the existing code.
- No change to `crew_freshness.py` or to the SessionStart status line. The new kind lives only in the per-ticket refresh check.
- No new config key, so `plugin/crew/CONFIG.md` does not change. The reference dir is `docs/reference`, as `reference.md:29` and `:60` already fix it.
- No change to `/crew:done`'s checks or wording. Check 4 already refuses any `stale` or `unknown` line (`plugin/crew/commands/done.md:46-57`).
- Hostnames stay as the code writes them. The lint refuses secrets only, and account ids follow the repo's own rules, not a new redaction pass.

## Unknowns
- T-0035 is not merged (INDEX row 34 is `ready`, direction only). Decided: T-0036 does not wait for it. Flow docs carry an inline `mermaid` block, which renders on GitHub and reads as text to an agent. T-0035's layout and embed generator adopt them later. This follows direction.md's own open-question proposal. Flagged for the owner at approval, because the INDEX row says "uses T-0035".
- The endpoint-ledger cross-check proposed in direction.md item 1. Decided: dropped, because the ledger holds exposed routes, not outbound hosts (Evidence). `--audit` compares `integrations.md` against the code instead. Flagged for the owner at approval.
- How far the allowance widens. Decided: `(None, "docs/reference")` becomes a fifth `REFRESH_ARTIFACT_PATHS` entry, so an approved ticket may write any file under `docs/reference/`, `api.md` and `features.md` included, without a Touch entry. The alternative is to widen only `docs/reference/flows`, which leaves `integrations.md`, a file, outside the allowance (`is_refresh_artifact` matches only paths strictly under a dir). That would make step 6's integrations refresh fail the scope guard. The same approval conditions apply: user-prompt approval, current, not `cli` without `scope.allowCliApproval`. These are pinned by must-block tests. Flagged for the owner at approval.
- Which docs are judged. Decided: `docs/reference/integrations.md` and `docs/reference/flows/*.md` only. Judging `api.md` and `features.md` would start refusing `/crew:done` in consumer repos whose existing docs are stale. That is a behaviour change nobody asked for in this ticket, so it is filed to `TODO.md` as a follow-up.
- A reference doc with no `Generated from <repo>@<sha>` header, or one citing no path, is `unknown` and refreshable, as the codemap's is. A repo with no outbound calls writes no `integrations.md`, and says so in the report, so an empty doc never exists to be judged. Pinned by tests.
- Secret detection has false negatives: a novel token format is not matched. The patterns cover AWS access key ids, PEM private-key blocks, GitHub tokens (`ghp_`, `github_pat_`), Slack tokens (`xox[abprs]-`), `sk-` style API keys, three-part JWTs, and a quoted literal assigned to a password, secret, token or API-key name. They also have false positives, since a documented example key is refused and the author writes a placeholder instead. The lint never prints the matched value. Accepted as risk. `crew:security` reviews every auth flow draft as a second line.
- The `--audit` extension (direction open question 3). Decided: yes. It reports calls in the code with no `integrations.md` entry, entries whose anchor no longer holds, and flow docs whose lint fails.
- Collisions:
  - T-0063 and T-0064 (approved) edit `crew_refresh_check.py`, and T-0068 (another agent's) reads the allowance definition. Many open tickets touch `implement.md`. Whichever lands second re-greps and rebases its edits. No Touch path here is owned by a ticket on the do-not-touch list.
  - Implement checks `.work/tickets/*/spec.md` again before editing.
- The guide rebuild needs `soffice` (`docs/guides/crew/src/build.py`), and only if a re-grep at implement finds a guide describing step 6 or `/crew:reference`. None does at `502cb137`. If one does and `soffice` is missing, implement stops as needs-owner.
