The Gizmoduck Plugin: An Overview for Everyone

Generated from useful-claude-add-ons@541b2b70 on 2026-09-22. Verify before trusting.
The high-level guide. No code knowledge needed. A companion technical reference covers the same ground in depth. Written against gizmoduck 0.5.3.

In one paragraph. Gizmoduck scans a website or host for known vulnerabilities, tells you what it found in plain terms, and — only after you say go — opens ServiceDesk Plus tickets for the ones worth fixing. It runs entirely on tools you install yourself; nothing is sent to a third-party scanning service, and nothing is ever ticketed without a person confirming the exact list first.

1. What It Does

  • Scans. Point it at a URL, a host, or a file listing several targets, and it runs Nuclei, a signature-based vulnerability scanner, against them.
  • Reports. It turns the raw findings into a report — on screen, as a web page, or as a PDF — ordered so the most serious finding is read first.
  • Tickets. For the findings serious enough to act on, it can open ServiceDesk Plus tickets, but only after showing you the exact batch and getting one explicit go-ahead.
  • Diffs. Given an old scan and a new one, it tells you what changed — the question "did we introduce anything new" answered directly, rather than by re-reading two full reports.

Only scan a website or host you own or have written permission to test.

2. How a Scan Goes

  1. You give it a target: a web address, a host name or IP, or a text file with one target per line.
  2. It runs the scan and writes every finding to a file, then shows you the counts by severity.
  3. It writes a report. Critical, High and Medium findings are described in full; Low and Informational findings are only counted, because a scanner's low-priority output is mostly inventory — version numbers, DNS records, "a form exists on this page" — and listing all of it buries what someone actually has to fix. The report always says how many were left out, so nothing goes missing quietly.
  4. If any findings are serious enough to be worth a ticket, it shows you the exact list — severity and one-line subject each — and a short code standing for that exact list. Nothing is created yet.
  5. You look at the list and say go. It reruns with that same code attached, and only then does it open or update the tickets. If anything about the list has changed in the meantime — a different scan, a different cut-off severity — the code no longer matches and it refuses, rather than silently ticketing a different batch than the one you approved.

3. What You Can Ask For

CommandWhat it does
/gizmoduck:scanScan a target, then report and offer to open tickets for the serious findings.
/gizmoduck:reportRebuild a report from a previous scan's findings, without scanning again.
/gizmoduck:ticketsConfirm, then open or update ServiceDesk Plus tickets from a findings file.
/gizmoduck:diffShow what is new since a previous scan.
/gizmoduck:updateUpdate the scan engine and its vulnerability signatures.
/gizmoduck:doctorCheck that everything the tool needs is actually installed.

4. Safety and Permission

  • Only scan what you are allowed to. The scanner is self-hosted and runs end to end with no export step, which also means there is no external gatekeeper stopping a scan of the wrong target — that responsibility sits with the person running it.
  • Ticketing asks first, always. Creating a real support ticket is never the default action. The tool shows the batch, waits for a person to look at it, and only proceeds against the exact list that was shown — never a wider or different one.
  • A degraded scan says so. If a supporting tool is not installed, gizmoduck records that clearly rather than pretending the check ran clean.

5. Getting It Working

  1. Run the installer once — bootstrap.sh on Linux/WSL, bootstrap.ps1 on Windows. It fetches the scan engine and its signature set, and the tool used to turn reports into PDF.
  2. Run /gizmoduck:doctor to confirm everything it found is actually usable.
  3. Point /gizmoduck:scan at a target you own or have written permission to test.

A free API key from the National Vulnerability Database speeds up one of the supporting checks considerably on a first run; it is optional, and gizmoduck says so rather than failing without one.

6. Glossary

TermMeaning
FindingOne reported issue: a template match, a version, a misconfiguration.
SeverityCritical, High, Medium, Low or Informational, from most to least serious.
BatchThe exact set of findings a ticketing run is about to act on.
DigestThe short code standing for one exact batch, so a rerun cannot silently widen it.
