The Rule-of-Two Plugin: An Overview for Everyone

The high-level guide. No code knowledge needed. A companion technical reference covers the same ground in depth. Written against rule-of-two 0.1.3.

In one paragraph. Rule-of-two has two AI reviewers from two different companies read the same skill, agent or plugin definition against the same checklist, without either seeing the other's notes, and tells you whether the artifact is worth shipping. Its whole job is to never claim two independent opinions when it only managed to get one — if the second reviewer could not run, the report says so in its own title, in plain words, rather than quietly presenting one opinion as two.

1. What It Is For

It reviews the building blocks of Claude Code itself — an agent definition, a skill, or a whole plugin — as artifacts, checking whether they are well-formed, whether their descriptions will actually trigger them, and whether they duplicate something that already exists. It does not review application code, architecture, or product ideas; the crew plugin's own reviewer, planner and architect roles are built for that.

2. Why Two Reviewers, and Why It Matters That They Differ

One AI reviewing its own kind of output can miss the same blind spots its own family has. Rule-of-two dispatches a Claude-family reviewer and a Codex-family reviewer at the same artifact, with no visibility between them, and then checks — mechanically, not by asking either model — whether the two really came from different families. In its own early self-reviews, the two reviewers agreed on very little at first look and, between them, found every blocking problem; neither one alone found all of them.

3. What You Can Ask For

CommandWhat it does
/rule-of-two:review <path>Runs both reviewers on an agent, skill or plugin and renders one combined report.
/rule-of-two:configShows which two models it will use, where that setting came from, and whether the second reviewer can actually run right now.

4. What the Report Is Honest About

  • Only one reviewer ran. If the second reviewer is missing, cannot authenticate, or its model has been retired, the report's own title says this is one review, not two.
  • The two reviewers turned out to be the same family after all. A same-family pairing is reported as one perspective wearing two names, and is called out as not meeting the bar.
  • It could not tell. If a reviewer's recorded identity does not resolve to a known family, the report says the question is unanswered — never quietly treated as a pass.

What the report cannot tell you: which underlying model actually served each request (only what was configured and asked for), or whether the review that ran actually inspected the artifact thoroughly rather than skimming it.

5. What It Needs to Work

  • The plugin installed, for the Claude-side reviewer to exist at all as a dispatchable role.
  • A working, authenticated codex command-line tool, for the second, independent reviewer.
  • Nothing from the crew plugin. Rule-of-two keeps its own configuration entirely separate.

6. Glossary

TermMeaning
CoverageThe report's own judgement of how independent the two reviews actually were, printed as one of a fixed set of outcomes.
FamilyWhich company's model line a reviewer belongs to — the thing that has to differ for "two independent reviews" to be true.

ArtifactThe agent, skill or plugin definition being reviewed — never the application code it might operate on.
