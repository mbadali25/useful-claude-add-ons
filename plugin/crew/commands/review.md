Run independent review of the working diff, last: after tests and docs, so the reviewer reads the finished change. Two rounds per ticket in total (`review_ledger.py`, shared by every worktree); a round is reserved before the reviewer launches, so a crashed one still counts, and a third is refused: `NEEDS_REPLAN`. Step 3.3 says how round 2's FINDINGS close. No flag, variable or config key changes it. The mechanics are `review_run.py`'s; the why is `docs/crew/review.md`. This file is the part that needs you.

**Step 0 - prepare.** Run `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/scripts/review_run.py --root . --prepare` (add `--ticket <id>` when I named one) and relay every line. It infers the one active ticket (zero or two: stop and ask), claims `SCRATCH`, finds the `BASE`, builds the bundle, `changed.txt` and `prompt.txt`, reserves nothing and launches no reviewer. Use the printed `SCRATCH` exactly; never recompute it. Then do what each `next:` line says, and after every `review_run.py` call do what its `next:` says. An exit 11 (`could not tell`) means an input could not be read: repair it, never guess.

**Say, in these words, what it printed.**
- `AUTHOR=<family> (<source>)`: `recorded dispatch <role>/<provider>/<model>` is a fact; `config` is `READ FROM CONFIG - no dispatch recorded`, a guess about the NEXT run, not who wrote this diff; `stale` (`STALE=1`) is `STALE RECORD - both families struck`; `unknown` is `author: UNKNOWN`, not a pass: no reviewer can be proven independent, the report sets `independentReviewer: false`, and pinning `dev.<provider>.model` fixes it. Never the family without its source.
- `VERIFY_MAP`: `absent` is `no verification map - run /crew:init; no specialist review was selected`; `read` with `SPECIALISTS=0` is `verification map read; no rule matched, so no specialist is required`. Never let "I could not look" read as "I looked and found nothing".
- Every `SPECIALIST=` line whose status is `MISSING` or `unknown` is a GAP: report it in step 3 beside the ones you skipped. Never drop it silently.

**Step 1 - specialists.** For each `SPECIALIST=<agent> installed files=...` line, run that subagent in its own context on those files only (a bare name is crew's own role first, then any installed agent; `plugin:name` is literal). The `Stop` hook cannot spawn a subagent, so `agents` is a review-time concern. Their BLOCKs count at step 3.3.

**Step 1b - the author's family is struck.** `ELIGIBLE` is the report's answer to "who may review this": `qa.order` walked, the family guard applied, in order. Do not re-derive it from `qa.provider`. A pinned provider that cannot run is an error, not a cue to fall back (except a `review` role pinned to codex: `--resolve-run` runs its fallback). Announce which reviewer ran and every provider you skipped, with the reason. An empty `ELIGIBLE` is `NO INDEPENDENT REVIEWER`: record it INCOMPLETE and refunded with `review_ledger.py --ticket "$TICKET" --no-reviewer --reason "<why>"`. A same-family read (step 2c) runs only on my `SAME_FAMILY="<reason>"`, is labelled `same_family`, and is never recorded as independent or written to `.crew/metrics.md` as though another family looked. Copilot with `qa.copilot.model` unset is a same-family reviewer in costume: skip it and say `copilot skipped: qa.copilot.model not set`; a `claude-` model is same-family and does not count.

**Step 2 - walk `ELIGIBLE`.** Do exactly the printed `next:`.

**Step 2a - Codex.** The `next:` gives a probe (`--probe`, one real call, no round: `command -v` is not a probe). Exit 0 runs the review; exit 5, 6 or 7 (limited, failed, unknown) skip Codex with `PROBE_DETAIL` quoted verbatim, then run `--resolve-run --probe-status <n>`, which prints `FALLBACK`, `RUN_PROVIDER` and `RUN_MODEL` for a pinned review role and the command to run. Any other exit is no answer about Codex: stop and quote it, never read it as ok or limited. A Claude read after a limit is my explicit choice: step 2c with `SAME_FAMILY="codex limit"`, announced `same-family (codex limit)`, not independent.

`reasoningEffort` accepts `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`;
Codex rejects a wrong one with an HTTP 400.

**Step 2b - Copilot.** Keeps `--deny-tool write --deny-tool shell`. Exiting non-zero with `Access denied by policy settings` is org or enterprise policy: report that exact cause.

**Step 2e - Kimi.** Needs no probe from you: `review_run.py` runs `kimi_probe.py` itself before reserving. A state other than `ok` exits 2: skip it, or hard-fail if `qa.provider` pins `kimi`. Exit 8, the probe changed the tree: stop and report the named paths; do not walk to the next provider. The reviewer reads the same `$SCRATCH/prompt.txt` as every provider; never re-word it for one. A Kimi round is never retried in-process.

**Step 2c - Claude reviewer** (cross-family, or same-family only on my `SAME_FAMILY`). Follow the printed `next:`: reserve the round BEFORE dispatching, invoke `crew:reviewer` with the exact `$SCRATCH/prompt.txt` plus the paths `$SCRATCH/diff.txt` and `$SCRATCH/manifest.json`, tell it to review that patch only (it must not run its own `git diff`), save its output as `$SCRATCH/out.txt`, then record it with `--round`. An empty `ROUND` means do not dispatch (refusal, or `ALREADY_CLEAN=1`). A refunded `tool` failure is re-dispatched once; any other INCOMPLETE stops. It is weaker than a different family: tell me when it ran.

**The verdict is the script's, not yours.** Read ONLY `$SCRATCH/out.txt` and the `review:` lines; never load the diff back. CLEAN only for exactly `CLEAN` at exit 0; any BLOCK/FIX/NIT is FINDINGS; a non-zero exit, empty output, a skipped part or a timeout is INCOMPLETE, never reported as clean. Exit 2 (nothing launched, no round spent), 9 (gate or pre-review checks), 10 (merge train) and 4 (`NEEDS_REPLAN`, terminal) are the reasons `next:` names.

**Step 2d - re-run the failing control, do not read about it.** If the diff adds or edits a test, guard, assertion or smoke step, the author is expected to have broken it on purpose and shown it go red; a pasted RED transcript is a claim, not the mutation. Where the check is runnable here, revert the guard's condition (or delete the line it asserts on), run it, confirm it fails with a message naming the thing under test, then restore. Report which controls you re-ran and which you took on the author's word. An unverified control is a BLOCK, not a NIT.

**Step 3 - act.**
1. **3.1** Report every BLOCK and FIX verbatim; do not soften or argue first. If `review: FINDINGS kept; ...` printed, show each ignored line verbatim (`ignored_text`). State the range and files **from `$SCRATCH/manifest.json`**: base, head, branch, dirty or not, each file's category.
2. **3.2** Land the verdict as a review, not a comment, if the change is on a PR: `gh pr review <PR> --request-changes --body-file "$SCRATCH/out.txt"` (any BLOCK) or `gh pr review <PR> --approve --body "<reviewer>: CLEAN"`. A `gh pr comment` is invisible to branch protection. Say which form; with no PR yet, say that.
3. **3.3 Closure (L-0510).** Fix all BLOCKs, run the gate, review once more: round 2 is the last. `review: auto-accept: eligible` and no BLOCK from step 1's specialists or step 2d's controls (the ledger never sees them): mint the next free id as `/crew:brainstorm` step 1 does, run `review_ledger.py --ticket "$TICKET" --auto-accept --follow-up <id>`, then `crew_tracker.py create --root . --ticket <id> --title "<title>"` and write its `direction.md`: source ticket, round, bundle sha, then every line printed after the first, verbatim, one per line in one fenced block (`--check-follow-up` matches whole lines). A same-family round is never eligible. `tracker not updated: <reason>` stops for me. Anything else (a BLOCK, a `refused -` line, a specialist BLOCK, an unverified control) stops for me with 2-4 options, recommended first, each with a one-line tradeoff (reject and replan / I accept as is / fix and I grant a round). If I accept: `review_ledger.py --ticket "$TICKET" --accept --by "<who>"` (the latest round, once; a `--by` starting `auto:` is refused). Rejecting: `--reject --by "<who>"`.
4. **3.4** If `notify.provider` is not `none`: `bash ${CLAUDE_PLUGIN_ROOT}/hooks/scripts/notify.sh review "<n> BLOCK, <n> FIX (<reviewer>)"`. Counts only, never the findings.
5. The metrics row is `review_run.py`'s: never append a scored row by hand. If it printed `metrics row NOT written` or `PARTLY written`, append exactly the row it quoted.
6. Run `crew_standards.py proposals --root . --ticket "$TICKET" --scratch "$SCRATCH" --round <N>` and fill each row as the `crew-standards` skill says; I approve each. An INCOMPLETE round's `out.txt` is refused.
7. Name every specialist that ran, every one a matched rule asked for that you skipped, and every one not installed on this machine (a GAP, recorded as a `-`-count row in the file the metrics line named). Name the author family **with its source** in the same breath as the reviewer, and a Codex-limit round as `claude (same-family: codex limit)` with the quoted `PROBE_DETAIL`.
